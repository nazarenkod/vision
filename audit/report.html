1. Резюме для керівництва і вердикт

Це третя перевірка Vision. Після попередньої ітерації (2026-11-07) змерджено дві специфікації безпеки: 051 (секрети, Jira, ліміт областей ігнорування, лінійний рушій виразів) і 052 (сесії на сервері, SSO лише у своїй вкладці, CSP і HSTS). Аудит виконано заново за тим самим промтом. Рішення власника й відкладені на майбутнє задачі не оцінювались (перелік — розділ 4.2).

Вердикт: ще не готовий до перенесення — два блокери, обидва невеликі за обсягом виправлення.

Обидва блокери — того самого класу, що й VIS-SEC-043 минулого разу, яку тоді вважали блокером: будь-який учасник проєкту (навіть роль guest чи API-ключ CI) одним запитом зупиняє API для всіх команд на секунди-хвилини, а серією запитів — валить процес через нестачу пам'яті. Обидва відтворено на стенді.

  1. VIS-SEC-058 (High). Новий «лінійний» рушій виразів зі специфікації 051 (RE2JS) справді не має експоненти, але приймає вирази на 300 символів, які компілюються в сотні тисяч інструкцій: один вираз — +46 МіБ у кеші (кеш на 500 виразів) і 1–7 с головного потоку. Через GET /test-runs/:id/selector-matches це доступно guest-у. Мета US-4 специфікації 051 (повільний вираз однієї команди не зупиняє API) не досягнута.
  2. VIS-SEC-043 (High, відкрито знову). Виправлення 2026-11-07 закрило лише один квадратичний шлях. Список, де рядки мають однаковий resource-id (типово для RecyclerView), знову квадратичний: 8000 рядків (2,2 МБ XML) — 18,8 с головного потоку на відкриття екрана.

Окремо специфікація 052 має дефект реалізації (VIS-SEC-059, Medium): збереження профілю видає новий токен, а старий не завершує, тож вихід після цього не гасить раніше скопійований токен — саме той сценарій, який 052 мала закрити. І зміна пароля не питає поточного пароля (VIS-SEC-060, Medium): після 052 той, хто вкрав токен, змінює пароль, лишається увійденим, а власника виганяє з усіх браузерів. Обидва відтворено на стенді.

2. Скоуп, методологія та обмеження

Скоуп: увесь код на коміті fe7a82c, з окремою увагою до диффу a3b6104..fe7a82c (143 файли, специфікації 051 і 052). Робочий VRT, його база, контейнери й картинки — поза скоупом і не чіпались. Реальні Jira, Gemini, Google Drive — не викликались.

Методологія.

  • Етап 1 — сканування (сирі виводи — audit/raw/*-2026-11-08*): npm audit prod і dev у трьох пакетах; semgrep 1.x з 977 локальних правил спільноти (javascript, typescript, java, python, dockerfile, bash, secrets, github-actions; без реєстру semgrep.dev); bandit по CLI; shellcheck по scripts/; власний regex-сканер секретів по всіх відстежуваних файлах (gitleaks запустити не дозволив запобіжник середовища); підрахунок ліцензій з package.json кожного встановленого пакета.
  • Етап 2 — ручний аудит чотирма паралельними агентами за розділами промту: A — автентифікація й сесії (2.1), B — авторизація, ізоляція, ін'єкції (2.2, 2.5; таблиця 88 маршрутів — raw/endpoints-2026-11-08.md), C — знімки, дерева, DoS, LLM, SSRF (2.3, 2.4), D — HTTP-шар, інфраструктура, supply chain, ліцензії (2.6–2.8). Кожна знахідка High/Medium перевірена мною окремо; три ключові — наживо.
  • Стенд: нативний Postgres 16 на 127.0.0.1:55434 із синтетичною базою, Node 24.11, випадкові JWT_SECRET і VISION_SECRET_KEY. Відтворення — тимчасовими e2e-файлами, видаленими після прогону: raw/repro-008-sessions-profile-password.txt, raw/repro-009-re2-cost.txt, raw/repro-010-structure-same-id.txt.

Обмеження.

  • Без Docker-демона — немає trivy image, compose і nginx-образ не запускались; заголовки nginx перевірено за конфігом і env.sh.
  • trivy, osv-scanner, gitleaks, hadolint, syft — бінарники з GitHub Releases завантажено, але запобіжник середовища не дозволив їх виконати. Замінено: npm audit (вразливості npm), власний regex-сканер (секрети), ручний огляд Dockerfile (агент D). SBOM не перегенеровано syft-ом: audit/sbom.cdx.json — з 2026-11-07 (805 компонентів), з тих пір додано одну залежність — re2js@2.9.1 (MIT, без залежностей), її дописано вручну (806). Gradle — без транзитивного графа (мережа), як і раніше.
  • Без історії git (рішення власника). LDAP/IdP не піднімались — LDAP/OIDC-знахідки з коду.
  • Playwright не запускався (браузерні тести не змінюють висновків безпеки).
  • Вимірювання DoS — короткі (до ~20 с), далі — екстраполяція з кількох точок.

3. Архітектура та модель загроз

Модель загроз і діаграма потоків — audit/threat-model.md і audit/assets/dfd.png (без змін складу компонентів). Після 052 додано один актив і одну межу:

  • Сесії (Session, sid у JWT) — тепер відкликання входу залежить від того, що кожен токен має живий рядок сесії. Загрози: сесії, які ніхто не завершує (VIS-SEC-059), необмежене зростання таблиці (VIS-SEC-062).
  • Вкладка браузера як межа SSO (nonce у sessionStorage) — закрила login CSRF (VIS-SEC-018).

Головна загроза цієї ітерації — доступність спільного інстансу: обчислення над даними, які задає клієнт (вирази правил, XPath, дерева), виконуються в головному потоці API, спільному для всіх команд і для сокета подій. Три з чотирьох нових Medium/High — саме тут.
