# ADR-0002: Робочий VRT лише читається

| | |
|---|---|
| Статус | Accepted |
| Дата | 2026-10-24 |
| Хто вирішив | Дмитро Назаренко |

## Контекст

Vision розгортається поруч із робочим VRT і має показувати реальні дані. Окремої машини немає.
Вимога власника: робочий VRT і його база не повинні постраждати за жодних умов.

## Чинники рішення

- Нуль ризику для проду.
- Реальні дані в демо.
- Розгортає одна людина без адміністратора.

## Розглянуті варіанти

1. Окремий сервер для Vision
2. Та сама машина, копія даних, прод лише читається, запобіжники в скриптах
3. Vision на живій базі проду

## Рішення

Друга опція. Прод лише читається: `pg_dump` у транзакції для читання з `nice 19`, кілька
`SELECT`, копія або жорсткі посилання на файли. Усі команди compose — лише через
`scripts/vision.sh` із закріпленим проєктом `vision` і перевіркою чужих контейнерів. Запас диска,
ліміти CPU й пам'яті, підтвердження `yes` перед руйнівними діями.

## Наслідки

- Добре: перевірено «відбитком» проду, що збігся на 100%.
- Погано: зайвий крок у кожній команді; діагностувати через `docker compose` напряму не можна.

## Як перевіряємо

Відбиток проду до й після ([011](../specs/011-deployment-safety/design.md)); hook агента блокує `docker compose` поза `vision.sh`.

## Варіанти: за і проти

### 1. Окремий сервер для Vision

- Добре: ізоляція від проду.
- Погано: сервера немає; копію даних однаково треба переносити.

### 2. Та сама машина, копія даних, прод лише читається, запобіжники в скриптах

- Добре: реальні дані; одна машина.
- Погано: спільні диск і CPU — потрібні запас диска й ліміти ресурсів.

### 3. Vision на живій базі проду

- Добре: жодного копіювання.
- Погано: будь-яка помилка Vision — помилка проду; неприйнятно.
