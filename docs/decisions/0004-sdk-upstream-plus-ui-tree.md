# ADR-0004: SDK — upstream плюс одне поле

| | |
|---|---|
| Статус | Accepted |
| Дата | 2026-10-25 |
| Хто вирішив | Дмитро Назаренко |

## Контекст

Автотести команд використовують upstream Java SDK, і версія прописана в `pom.xml`. Вимога
власника: у SDK змінюється лише одне — з'являється необов'язковий параметр з XML.

## Чинники рішення

- Наявні тести не переписуються.
- Перехід — заміна jar.

## Розглянуті варіанти

1. Лише `TestRunOptions.uiTree`
2. Додати `trackDriver(driver)`, `failOnNewA11yIssues`
3. Окремий SDK Vision

## Рішення

Перша опція: `uiTree` — єдина зміна відносно upstream 4.3.1. SDK стискає XML (gzip + base64);
формат і щільність визначає сервер. Jar — у `dist/sdk-java/` (`4.3.1-vision.N`).

## Наслідки

- Добре: дерево додається одним рядком.
- Погано: сервер мусить сам визначати формат і щільність, оцінюючи її, якщо `deviceDensity` немає.

## Як перевіряємо

`git diff` `sdk-java/` проти upstream 4.3.1 містить лише `uiTree` і його тести.

## Варіанти: за і проти

### 1. Лише `TestRunOptions.uiTree`

- Добре: нульова зміна для тестів.
- Погано: зручні помічники не з'являються.

### 2. Додати `trackDriver(driver)`, `failOnNewA11yIssues`

- Добре: зручніше.
- Погано: нове API, нові залежності (Selenium), розходження з upstream.

### 3. Окремий SDK Vision

- Добре: свобода.
- Погано: дві бібліотеки, міграція тестів.
