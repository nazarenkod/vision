# ADR-0005: Перевірка за назвою, еталон на кожен пристрій

| | |
|---|---|
| Статус | Accepted |
| Дата | 2026-10-25 |
| Хто вирішив | Дмитро Назаренко |

## Контекст

У кожного екрана є еталони на емуляторі або симуляторі та на BrowserStack-пристрої. Порівнювати
пікселі між різними пристроями не можна, а правила й рішення хочеться мати одні на екран.

## Чинники рішення

- Точне піксельне порівняння.
- Одні правила й рішення на екран.
- Без міграції наявних даних.

## Розглянуті варіанти

1. Ключ upstream: кожен пристрій окремо
2. Перевірка = назва + теги, еталон на кожен пристрій
3. Один еталон на перевірку для всіх пристроїв

## Рішення

Друга опція. Варіації upstream не змінюються; перевірка — обчислений ключ
`checkKey(name, customTags)`. Правила елементів і рішення щодо доступності належать перевірці.

## Наслідки

- Добре: без міграції; пристрій без еталона все одно перевіряється на доступність і «не той екран».
- Погано: перейменування тесту — нова перевірка.

## Як перевіряємо

Тести `checkGrouping.test.ts`, `test-runs.service.spec.ts › keeps a rule for this screen by check…`.

## Варіанти: за і проти

### 1. Ключ upstream: кожен пристрій окремо

- Добре: нічого не змінювати.
- Погано: правила й рішення дублюються.

### 2. Перевірка = назва + теги, еталон на кожен пристрій

- Добре: точність і спільні правила.
- Погано: назва тесту стає значущою.

### 3. Один еталон на перевірку для всіх пристроїв

- Добре: менше еталонів.
- Погано: пікселі різних пристроїв не порівнюються.
