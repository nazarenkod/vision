# ADR-0008: Стабільні ID проблем і ідентичність з фактів

- **Статус:** Accepted
- **Дата:** 2026-10-26

## Контекст

Перша версія обчислювала ID проблеми з ключа, а ключ залежав від налаштувань (режим дублів,
класи). Зміна налаштувань змінювала ID і відривала заведені баги. Команда хоче гнучко
налаштовувати, що вважати однією проблемою, і робити це без втрат.

## Рішення

- ID видається один раз, при створенні проблеми, і зберігається.
- Проблема зберігає **факти** місць, для яких її вирішили: правило, id елемента, компонент,
  екран, замір, клас, підпис.
- Що є однією проблемою, обчислюється щоразу: `problemKeyOf(факти, поточні налаштування)` — і для
  знахідок, і для збережених проблем (індекс у пам'яті, кеш за версією).
- Налаштування — це правила за замовчуванням для кожного правила доступності плюс класи з
  комбінацією шаблонів.

## Наслідки

- Зміна налаштувань перегруповує, але не втрачає: склеєні проблеми показують усі свої баги,
  розділені — тримають баг за кожною частиною.
- Unlink частини розділеної проблеми прибирає лише цю частину фактів.
- Ціна: на кожне рев'ю будується індекс проблем проєкту (кешується; перебудова — лише після змін).
