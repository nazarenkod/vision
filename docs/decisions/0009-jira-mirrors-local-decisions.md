# ADR-0009: База Vision — джерело правди, Jira — дзеркало

| | |
|---|---|
| Статус | Accepted |
| Дата | 2026-10-26 |
| Хто вирішив | Дмитро Назаренко |

## Контекст

Баги заводять кілька людей одночасно, іноді руками або з іншої інсталяції. Пошук у Jira
повільніший, обмежений правами токена й буває недоступним. Відв'язаний баг не має прив'язуватися
знову.

## Чинники рішення

- Нуль дублів.
- Робота без Jira.
- Відв'язане лишається відв'язаним.
- Аудит рішень.

## Розглянуті варіанти

1. Jira — джерело правди: щоразу шукати
2. База Vision — джерело правди, «замок» у базі, мітки в Jira, пошук за ID і маркерами
3. Лише база, без пошуку в Jira

## Рішення

Друга опція. Рішення — в `A11yProblem`, журнал — в `A11yDecision`, «замок» — унікальний ключ.
Jira отримує мітки (ID і маркери) при створенні та Link, а при Unlink — `a11y-unlinked-<id>`
замість маркерів. Пошук у Jira — перед заведенням і при рев'ю (кеш 10 хв, таймаут 5 с). Баг,
відв'язаний у журналі, автоматично не прив'язується ніколи.

## Наслідки

- Добре: без Jira Vision працює; збій міток — попередження.
- Погано: баг поза Vision знаходиться лише з ID або повним набором маркерів.

## Як перевіряємо

`a11y-problems.service.spec.ts` (гонка, пошук, Unlink); SC-004-01 — JQL раз на місяць.

## Варіанти: за і проти

### 1. Jira — джерело правди: щоразу шукати

- Добре: одне джерело.
- Погано: повільно; без Jira не працює; гонка двох людей не закрита.

### 2. База Vision — джерело правди, «замок» у базі, мітки в Jira, пошук за ID і маркерами

- Добре: швидко, атомарно, знаходить зовнішні баги.
- Погано: два місця даних; мітки можуть розійтися.

### 3. Лише база, без пошуку в Jira

- Добре: просто.
- Погано: баги, заведені руками, дублюються.
