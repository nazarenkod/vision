# ADR-0010: Особисті токени Jira

- **Статус:** Accepted
- **Дата:** 2026-10-26

## Контекст

Зі спільним токеном проєкту всі баги заводились би від імені однієї людини, а права в Jira були б
однакові для всіх.

## Рішення

Кожен користувач зберігає свій токен (і email для Cloud) у профілі. Vision звертається до Jira
від імені того, хто діє: заведення, Link і Unlink, пошук людей, пошук під час рев'ю. Спільний токен
проєкту необов'язковий: його беруть, лише коли в людини немає свого. Токени лише записуються, API
повертає `jiraTokenSet`.

## Наслідки

- У Jira видно справжнього автора, діють його права.
- Пошук під час рев'ю залежить від токена того, хто дивиться.
- Токени поки лежать у базі відкритим текстом: шифрування заплановано в [013](../specs/013-backups-and-secrets/spec.md).
- Попутно історія еталонів більше не віддає рядок користувача цілком.
