# ADR-0011: Скриншот-еталони Playwright — лише з Docker

| | |
|---|---|
| Статус | Accepted |
| Дата | 2026-10-24 |
| Хто вирішив | Дмитро Назаренко |

## Контекст

Рендеринг шрифтів на macOS і Linux різний, тому локальні скриншоти ніколи не збігаються з
еталонами CI.

## Чинники рішення

- Стабільні еталони.
- Локальний прогін функціональних тестів.

## Розглянуті варіанти

1. Еталони з macOS
2. Лише з Docker (образ Playwright тієї ж версії)
3. Без скриншот-тестів

## Рішення

Друга опція. Еталони — `frontend/test-docker.sh --update-snapshots` у чистій копії
репозиторію. Локально скриншот-тести падають, функціональні — мусять проходити.

## Наслідки

- Добре: еталони однакові для всіх.
- Погано: оновлення еталона — окремий крок у Docker.

## Як перевіряємо

Еталон міняється лише в коміті зі зміною знятого екрана; отриманий знімок переглянуто.

## Варіанти: за і проти

### 1. Еталони з macOS

- Добре: швидко.
- Погано: CI на Linux завжди червоний.

### 2. Лише з Docker (образ Playwright тієї ж версії)

- Добре: відтворювано.
- Погано: повільніше; треба чиста копія репозиторію.

### 3. Без скриншот-тестів

- Добре: просто.
- Погано: регресії вигляду не ловляться.
