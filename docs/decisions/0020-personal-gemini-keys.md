# ADR-0020: Особисті ключі Gemini для чернеток багів

| | |
|---|---|
| Статус | Accepted |
| Дата | 2026-10-29 |
| Хто вирішив | Дмитро Назаренко |

## Контекст

AI у Vision налаштовано на інстанс ([010](../specs/010-ai-assist/spec.md)): один провайдер, один
ключ і денний ліміт на всіх. Ключ Gemini в налаштуваннях проєкту існує лише для движка
порівняння VLM. Чернетку бага з порівняння ([025](../specs/025-bug-from-comparison/spec.md))
просить конкретна людина, і власник хоче, щоб вона робила це своїм ключем, а не ключем проєкту
чи інстансу.

## Чинники рішення

- Кожен вирішує, скільки AI коштує йому; витрати не змішуються в одному ключі.
- Ключ — секрет: не виходить із сервера (правило 7, як токени Jira в [ADR-0010](0010-personal-jira-tokens.md)).
- Решта AI (пояснення груп змін, підписи іконок, VLM) не змінюється.

## Розглянуті варіанти

1. Ключ інстансу, як для інших функцій AI
2. Ключ проєкту (той, що для VLM)
3. Особистий ключ у профілі, без запасного

## Рішення

Третя опція. Ключ Gemini API людина зберігає в профілі; API лише приймає його й повертає
`geminiKeySet`. Чернетка бага йде на Gemini з цим ключем незалежно від провайдера інстансу; без
ключа діалог пропонує додати його в профілі й працює без AI. Денний ліміт інстансу ці запити не
обмежує: квота — ключа людини. Відповіді кешуються так само, як інші ([010](../specs/010-ai-assist/spec.md)).

## Наслідки

- Добре: витрати прозорі й особисті; AI для багів не залежить від того, що налаштовано на інстансі.
- Добре: ключ проєкту лишається лише для порівняння VLM.
- Погано: кожен, хто хоче AI в багах, має отримати власний ключ у Google AI Studio.
- Погано: дві схеми AI в одному продукті — інстанс для пояснень, особисті ключі для багів.

## Як перевіряємо

`backend/src/ai/ai.service.spec.ts › refuses a bug draft without the person’s own Gemini key` і
`backend/src/ai/ai.service.spec.ts › drafts on the person’s own key whatever the instance runs, outside its daily limit`;
`backend/src/users/users.controller.spec.ts › stores a personal Gemini key and answers only whether one is set`.

## Варіанти: за і проти

### 1. Ключ інстансу

- Добре: нічого нового.
- Погано: спільні витрати й ліміт; власник хоче інакше.

### 2. Ключ проєкту

- Добре: уже є поле.
- Погано: витрати всієї команди в одному ключі; ключ VLM отримує другу роль.

### 3. Особистий ключ у профілі

- Добре: свої витрати, свій вибір.
- Погано: кожному потрібен ключ.
