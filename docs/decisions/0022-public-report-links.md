# ADR-0022: Публічний звіт збірки: посилання з токеном, без входу, PDF друком

| | |
|---|---|
| Статус | Accepted |
| Дата | 2026-10-31 |
| Хто вирішив | Дмитро Назаренко |

## Контекст

Звіт про збірку ([031](../specs/031-build-overview/spec.md)) мають читати люди без акаунта у Vision,
наживо й з відкликанням. Досі всі дані Vision, крім файлів знімків (upstream
`/images/:name`), віддавались лише після входу. Сокет-шлюз розсилає рядки всіх збірок усім, хто
під'єднався. Upstream сам видаляє збірки за лімітом, і нові обмеження в базі не повинні цьому
заважати ([ADR-0003](0003-additive-schema-only.md)). Звіт ще й треба віддавати PDF.

## Чинники рішення

- За посиланням не повинно бути видно нічого, крім звіту однієї збірки.
- Посилання не можна вгадати чи вивести з номера збірки.
- Upstream-видалення збірок і людей мусить працювати як раніше.
- На машині з продом — жодних нових важких залежностей (headless-браузер).

## Розглянуті варіанти

1. Підписане посилання (JWT зі збіркою й терміном) без таблиці.
2. Таблиця посилань із випадковим токеном, без зовнішніх ключів; один публічний ендпоінт.
3. Гостьовий акаунт із роллю guest на кожне посилання.

PDF: (а) друк сторінки браузером, (б) генерація на сервері headless-браузером, (в) бібліотека PDF у браузері.

## Рішення

Обрано варіант 2 і PDF (а).

- `ReportLink` з токеном на 256 біт, розділами, мовою, автором, `revokedAt`. Терміну дії немає:
  посилання працює, доки зберігається збірка (рішення 2026-11-01).
  Відкликати можна, бо посилання — рядок у таблиці (у варіанті 1 це неможливо без чорного списку).
- Без зовнішніх ключів на `Build` і `User`: видалена збірка дає «збірки більше немає».
- Єдиний ендпоінт без входу — `GET /public/reports/:token`. Відповідь будується з білого списку
  полів; людей названо лише на ім'я.
- Публічна сторінка не під'єднується до сокета, а перепитує зведення з `ETag`.
- PDF — друк сторінки звіту зі стилем `@page A4`: те саме, що на екрані, і без нових залежностей.

## Наслідки

- Добре: відкликання працює одразу; видалення збірок не змінюється; PDF без залежностей.
- Погано: це перший ендпоінт даних без входу, тож кожне нове поле в ньому — свідоме рішення.
  «Save as PDF» — один зайвий крок у діалозі друку, і вигляд трохи залежить від браузера.
- Знімки за посиланням віддаються наявним `/images/:name`, як і раніше без входу; ім'я файлу —
  випадковий UUID.

## Як перевіряємо

- `report-links.spec.ts`: у відповіді публічного звіту немає `email`, `apiKey`, `token`, `jira*`;
  прострочене й відкликане посилання не віддає даних.
- `reports.controller.spec.ts`: публічний маршрут — єдиний без guard у модулі.
- Рев'ю: нове поле в публічній відповіді потребує рядка в білому списку й тесту.

## Варіанти: за і проти

### 1. Підписане посилання

- Добре: без таблиці.
- Погано: не відкликати; список посилань збірки не показати (REQ-031-66).

### 2. Таблиця з токеном

- Добре: відкликання, перелік, термін, аудит.
- Погано: нова таблиця, перший публічний ендпоінт.

### 3. Гостьовий акаунт

- Добре: наявні guard'и.
- Погано: гість бачить усі проєкти; акаунти розмножуються; немає терміну.

### PDF (б) headless-браузер на сервері

- Добре: файл одним кліком.
- Погано: Chromium на машині з продом, пам'ять, оновлення безпеки.

### PDF (в) бібліотека в браузері

- Добре: файл одним кліком.
- Погано: друга верстка звіту, яка розходиться з екраном; сотні КБ залежності.
