# ADR-0024: SDK відходить від upstream VRT кроками; перший — головні класи `Vision`

| | |
|---|---|
| Статус | Accepted |
| Дата | 2026-11-01 |
| Хто вирішив | Дмитро Назаренко |

## Контекст

[ADR-0019](0019-sdk-upstream-plus-ui-tree-and-feature.md) тримав SDK як upstream VRT 4.3.1 плюс
два необов'язкові поля й забороняв інші зміни API, щоб команди лише замінили jar. Тепер власник хоче
відв'язати Vision від VRT: у тестах видно `VisualRegressionTracker` і `VisualRegressionTrackerConfig`.
Розглядали й повне перейменування (пакет, методи, `TestRun*`, `VISION_*`, нові координати), але
власник обрав рухатися малими кроками. Специфікація першого кроку —
[033](../specs/033-vision-sdk/spec.md).

## Чинники рішення

- Власна назва головного об'єкта в коді тестів.
- Кожен крок малий: перехід тесту — кілька механічних замін, еталони не скидаються.
- Сервер не змінюється; запити SDK ті самі.
- Подальші зміни API можливі, але кожна — окремим рішенням власника зі специфікацією.

## Розглянуті варіанти

1. Кроками: зараз лише `Vision` і `VisionConfig`, решта — пізніше окремими специфікаціями
2. Одним кроком перейменувати весь публічний API, конфіг і координати
3. Новий SDK з нуля поруч із замороженим старим

## Рішення

Обрано варіант 1. `VisualRegressionTracker` → `Vision`, `VisualRegressionTrackerConfig` →
`VisionConfig`; класів зі старими назвами немає. Пакет, методи, інші класи, змінні `VRT_*`, `vrt.json`
і Maven-координати не змінюються, версія — `4.3.1-vision.3`. Обмеження ADR-0019 «інших змін API не
робимо» знято: SDK може відходити від upstream далі, але лише через специфікацію, затверджену
власником.

## Наслідки

- Добре: головний об'єкт називається як інструмент; перехід — дві назви класів та імпорти.
- Добре: крок малий, запити ті самі, тож еталони й сервер не зачеплено.
- Погано: тести на `4.3.1-vision.2` не компілюються з новим jar без заміни назв.
- Погано: `sdk-java` більше не оновлюється з upstream через subtree без конфліктів
  ([ADR-0001](0001-fork-as-subtree-monorepo.md)).
- Погано: назви VRT (`TestRun*`, пакет, `VRT_*`) лишаються до наступних кроків.

## Як перевіряємо

Тест SDK перевіряє, що класів `VisualRegressionTracker` і `VisualRegressionTrackerConfig` у jar
немає; решта тестів, що перевіряють JSON запитів, не змінились, крім назв класів. `git diff`
`sdk-java/src/main` проти upstream 4.3.1 містить лише `uiTree`, `featureName` і назви двох класів,
доки не прийнято наступну специфікацію.

## Варіанти: за і проти

### 1. Кроками

- Добре: кожен крок малий і перевірюваний; команди переходять без великих переписувань.
- Погано: кілька перевипусків jar, і кожен трохи змінює тести.

### 2. Усе одним кроком

- Добре: одразу власна мова в усьому API.
- Погано: великий перехід для команд; власник поки не готовий.

### 3. Новий SDK з нуля

- Добре: чистий новий API.
- Погано: дві кодові бази; найбільший перехід.
