# ADR-0026: SDK — власний пакет, координати й нумерація, без старих назв

| | |
|---|---|
| Статус | Accepted |
| Дата | 2026-11-05 |
| Хто вирішив | Дмитро Назаренко |

## Контекст

[ADR-0024](0024-own-vision-sdk.md) почав відходити від upstream VRT кроками: головні класи вже
`Vision*`, але пакет `io.visual_regression_tracker.sdk_java`, змінні `VRT_*`, файл `vrt.json`,
Maven-координати `com.github.Visual-Regression-Tracker:sdk-java` і версія `4.3.1-vision.N` ще
називають чужий продукт. Vision іде в банківський контур, і власник вирішив, що від VRT
лишаються лише `LICENSE` і `NOTICE` ([план](../security/bank-readiness-plan.md)). Тестові проєкти
переходять на новий jar разом із запуском нової версії сервера. Специфікація —
[040](../specs/040-uitree-limits-and-sdk-names/spec.md).

## Чинники рішення

- Жодної назви VRT у коді, конфігурації й логах тестових проєктів.
- Тестові проєкти оновлюються один раз, разом із лімітом UI-дерева.
- Запити до сервера ті самі: еталони не скидаються.
- Підтримувати дві назви — це вічний код сумісності, а власник від нього відмовився.

## Розглянуті варіанти

1. Новий пакет, координати й нумерація; старих назв немає
2. Нові назви плюс старі як запасні (читати і `VISION_*`, і `VRT_*`)
3. Лишити пакет і координати, змінити тільки змінні й лог

## Рішення

Обрано варіант 1: пакет `ua.vision.sdk`, координати `ua.vision:vision-sdk`, версії від `1.0.0`,
змінні `VISION_*`, файл `vision.json`, лог «Vision». Старих назв SDK не читає й не містить. Класи,
методи, поля й запити не змінюються; інші зміни API — як і раніше, лише за специфікацією.

## Наслідки

- Добре: у тестах і їхній конфігурації — лише Vision; версія SDK більше не прив'язана до upstream.
- Погано: перехід — заміна `import`, залежності в `pom` і назв змінних у CI; старий jar треба
  прибрати з тестових проєктів.

## Як перевіряємо

`VisionTest › livesInTheVisionPackageOnly` (класів у старому пакеті немає),
`VisionConfigTest › ignoresVrtVariables`, `test_build_sdk_jar.py` (координати й версія),
контрольний сценарій (ті самі запити й результати).

## Варіанти: за і проти

### 2. Нові назви плюс старі

- Добре: тестові проєкти можна оновлювати поступово.
- Погано: назви VRT лишаються в SDK; власник вирішив оновити все разом.

### 3. Лише змінні й лог

- Добре: менше замін у тестах.
- Погано: `import io.visual_regression_tracker…` лишається в кожному тесті.
