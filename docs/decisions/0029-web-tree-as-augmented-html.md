# ADR-0029: Дерево вебсторінки — HTML з доповненнями, а не власний JSON

| | |
|---|---|
| Статус | Accepted |
| Дата | 2026-11-15 |
| Хто вирішив | Дмитро Назаренко |

## Контекст

Vision має приймати дерево вебсторінки (050). Звичайний `page source` Selenium — HTML без
координат, вмісту `iframe` і shadow DOM, а без координат не працюють зсуви, вибір елемента,
контраст і область дотику. SDK може зібрати в браузері більше, але треба вирішити, у якому
вигляді.

## Чинники рішення

- `page source` без SDK теж має прийматися (REQ-050-01, REQ-050-09).
- Той самий розбір для Selenide і Playwright (REQ-050-24).
- Межі прийому й зберігання — ті самі, що для Appium (040).
- `xpath:` і шляхи безіменних елементів мають працювати, як для мобільних.

## Розглянуті варіанти

1. Власний JSON вузлів (тег, атрибути, rect) — новий парсер і окремий формат від `page source`.
2. HTML у тому вигляді, як його дає браузер, з атрибутами `data-vision-*` для координат,
   масштабу й прокрутки; shadow DOM — у `<template shadowrootmode>`, `iframe` — його `<html>`
   усередині.

## Рішення

Обрано варіант 2: один парсер для `page source` і для дерева з SDK; дерево без SDK — той самий
формат, лише без `data-vision-*`. Декларативний shadow DOM — стандарт HTML, тож дерево
читається будь-яким HTML-інструментом.

## Наслідки

- Добре: один розбір, ті самі ключі й шляхи, що дає `page source`; людина може відкрити дерево
  в браузері.
- Погано: HTML більший за стислий JSON — лікується gzip і тим, що скрипт не серіалізує
  `script`, `style` і вміст прихованих елементів; DOCTYPE для HTML у прийомі дозволено
  окремим правилом.

## Як перевіряємо

`backend/src/ui-tree/web-tree.parser.spec.ts` (той самий розбір для `page source` і дерева з
SDK), `sdk-playwright/test/collect.spec.ts` (скрипт збору — один для обох SDK).
