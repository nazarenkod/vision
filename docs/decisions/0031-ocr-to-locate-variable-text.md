# ADR-0031: OCR на сервері, щоб знайти на знімку позначені шматки тексту

| | |
|---|---|
| Статус | Accepted |
| Дата | 2026-11-17 |
| Хто вирішив | Дмитро Назаренко |

## Контекст

Правило «Нестабільний текст» знає межі тексту лише з UI-дерева. Застосунки часто зливають рядок
списку в один вузол доступності (історія операцій банку: `Button #activity_list_item` з текстом
лише в `content-desc`), і тоді не порівнюється весь рядок
([071](../specs/071-variable-text-found-on-screenshot/spec.md)). Межі позначених шматків є лише на
самому знімку. 2026-11-17 Tesseract (через `tesseract.js`) знайшов усі 18 позначених місць на двох
реальних знімках цього екрана, ~0,3 с на рядок.

## Чинники рішення

- Детермінованість і жодного LLM при прийомі знімків ([ADR-0007](0007-deterministic-first-ai-on-demand.md)).
- Знімки банку не залишають сервер; закрита мережа без доступу до CDN.
- Прод VRT на тій самій машині не повинен відчути навантаження ([ADR-0002](0002-production-is-read-only.md)).
- Ліцензія, сумісна з Apache-2.0 Vision.

## Розглянуті варіанти

1. `tesseract.js` (WebAssembly) з моделями з npm у `node_modules`.
2. Системний `tesseract` у образі й виклик процесом.
3. Хмарні OCR (Google Vision, AWS Textract).
4. Вгадувати межі з різниці пікселів (чернетка, від якої відмовились).

## Рішення

Обрано варіант 1: ставиться як звичайна залежність npm, без змін базового образу; моделі
`@tesseract.js-data/ukr` і `eng` (`4.0.0_best_int`) лежать у `node_modules`, шлях до них
локальний, тож бібліотека не ходить у мережу. Версії бібліотеки й моделей — точні. OCR лише шукає
межі вже відомого з дерева тексту в елементах під правилом нестабільного тексту; читати текст з
пікселів для будь-чого іншого Vision не стає.

## Наслідки

- Добре: детерміновано, офлайн, Apache-2.0 (бібліотека) і MIT (пакети моделей), ~5 МБ моделей.
- Добре: якщо OCR не впорався, поведінка — як до 071 (не порівнюється весь елемент).
- Погано: ~150 МБ пам'яті API, поки живе обробник; до ~0,5 с CPU на рядок.
- Погано: оновлення бібліотеки чи моделей може зсунути межі слів — оновлюємо лише з тестом.

## Як перевіряємо

`backend/src/ui-tree/text-locator.service.spec.ts` розпізнає фікстуру рядка без мережі й звіряє
межі; `package.json` тримає точні версії; рев'ю будь-якого нового використання OCR — за цим ADR.

## Варіанти: за і проти

### 1. `tesseract.js`

- Добре: лише npm, працює в Node без системних пакетів, той самий код на Mac і в Docker.
- Погано: повільніший за нативний на ~20–40 %.

### 2. Системний `tesseract`

- Добре: швидший.
- Погано: зміна базового образу, `apt` у закритій мережі, окремий процес і його версія поза npm.

### 3. Хмарні OCR

- Погано: знімки банку йдуть назовні; мережа закрита.

### 4. Межі з різниці пікселів

- Погано: евристика з порогами; нічого не показати, поки текст не змінився.
