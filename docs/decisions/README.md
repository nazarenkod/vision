# Рішення (ADR)

Architecture Decision Record фіксує важливе рішення: контекст, саме рішення та його наслідки.
Прийнятий ADR не редагуємо. Якщо рішення змінилось, пишемо новий ADR, а старий отримує статус
`Superseded by ADR-NNNN`.

Писати ADR варто, коли рішення:
- накладає обмеження на майбутню роботу («лише додавальна схема»);
- обирає з кількох розумних варіантів і має ціну («особисті токени, а не спільний»);
- інакше доведеться пояснювати знову в кожному код-рев'ю.
