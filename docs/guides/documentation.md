# Як писати документацію

## Поступове розкриття

Читач — людина чи агент — спершу бачить мінімум, а за посиланнями отримує стільки деталей,
скільки потрібно задачі. Для агента це ще й ціна: усе, що лежить на рівні 0, займає контекст у
кожній сесії.

| Рівень | Файли | Обсяг | Що там |
|---|---|---|---|
| 0 | `AGENTS.md` (корінь і пакети), `CLAUDE.md` | до ~100 рядків кожен (Claude Code радить < 200) | правила, що діють завжди; команди; пастки; куди далі |
| 0½ | описи skills (`.claude/skills/*/SKILL.md`, поле `description`) | одне речення | коли запускати процедуру; тіло читається лише під час виклику |
| 1 | `docs/README.md`, `product/`, `architecture/overview.md` | 1–2 екрани | карта, терміни, загальна будова |
| 2 | `specs/`, `decisions/`, `architecture/data-model.md`, `api.md`, `guides/` | скільки потрібно | деталі однієї теми |

Правила:
- **Рівень 0 — лише те, що потрібне в кожній задачі.** Багатокрокова процедура — це skill.
  Деталь, потрібна раз на місяць, іде на рівень 2 з посиланням.
- **Правило, порушення якого не виправити, забезпечуємо hook'ом**, а не лише текстом
  (`.claude/hooks/guard.py`). Інструкції — це контекст, а не обмеження.
- **Документ починається з того, що це і коли його читати,** далі — найважливіше.
- **Один факт — одне місце.** Команди пакета — в його `AGENTS.md`; поведінка — у `spec.md`; як
  зроблено — у `design.md`; чому — в ADR. Решта посилається.
- **Посилання замість копій:** скопійований текст розходиться з оригіналом.
- **Конкретно:** шляхи, назви функцій, точні команди, числа з коду (48 dp, 10 хв).
- **Один документ — один тип** за [Diátaxis](https://diataxis.fr/): інструкція, довідка або
  пояснення, а не все разом.
- Таблиці — для переліків, списки — для кроків, абзаци — для «чому».

## Хто що оновлює

| Сталося | Онови |
|---|---|
| Нова або змінена поведінка | `spec.md` (вимоги, історії) і `design.md` (компоненти, «Перевірка вимог»); статус |
| Рішення з наслідками чи обмеження | новий ADR за `decisions/template.md` + рядок у `decisions/README.md` |
| Нова таблиця, колонка, файл, ендпоінт | `architecture/data-model.md`, `api.md` |
| Нова команда, пастка, правило пакета | `AGENTS.md` пакета |
| Нове непорушне правило | `AGENTS.md` (корінь), hook і його тест |
| Змінилось розгортання чи налаштування для користувача | `DEPLOY.md` (рос.), за потреби `DEMO.md` |
| Новий термін | `product/glossary.md` |
| Перейменовано тест або файл | `python3 -I scripts/check-docs.py` покаже, де оновити |

## Мова

- Документація для команди — українською. `DEPLOY.md` лишається російською, поки його так
  читає людина, що розгортає; `DEMO.md` — англійською, для показу.
- Ідентифікатори, поля, команди й тексти інтерфейсу — як у коді, англійською.
- Описи skills (`description`) — англійською: так Claude Code надійніше обирає skill.

## Перевірка

`python3 -I scripts/check-docs.py` перевіряє:
- відносні посилання в усіх `.md`;
- статуси специфікацій і ADR, індекси в `specs/README.md` і `decisions/README.md`;
- унікальність ID вимог і їхню належність специфікації;
- що кожна вимога не-чернетки простежена в `design.md`, а названі тести й шляхи існують;
- обов'язкові розділи ADR.

Запускається в `/verify` і в CI (`.github/workflows/docs.yml`). У Claude Code аудит інструкцій
(суперечності, застарілі правила) дає `/doctor prompt-audit`.
