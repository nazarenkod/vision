# Словник

Терміни upstream VRT і Vision. У коді — англійські назви з дужок. Як ці терміни звучать в
українському інтерфейсі — [глосарій перекладу](../specs/023-ukrainian-ui/design.md#глосарій-перекладу).

## Upstream VRT

| Термін | Значення |
|---|---|
| Проєкт (`Project`) | набір збірок і варіацій; у нас Android і iOS — окремі проєкти |
| Збірка (`Build`) | один прогін тестів: набір знімків |
| Знімок, прогін (`TestRun`) | результат порівняння одного скриншота з еталоном |
| Варіація (`TestVariation`) | історія еталонів для назва + гілка + OS + браузер + viewport + пристрій |
| Еталон (`Baseline`) | прийнятий скриншот; останній — очікуваний результат |
| Ігноровані області (`ignoreAreas`) | прямокутники, які не порівнюються |

## Vision

| Термін | Значення |
|---|---|
| Перевірка (check) | те, що назвав тест: назва + `customTags`. Пристрої — прогони однієї перевірки ([001](../specs/001-check-identity/spec.md)) |
| Профіль пристрою (device profile) | OS + пристрій + браузер + viewport прогону |
| Еталонний пристрій (reference device) | пристрій, з яким довідково порівнюються інші ([007](../specs/007-cross-device-reference/spec.md)) |
| UI-дерево (`uiTree`) | Appium page source (XML), надісланий разом зі скриншотом |
| Елемент, ключ елемента (`nodeKey`) | `id:<resource-id або Compose tag>`, інакше `Class:текст` або `path:…`; повтори того ж id — `#1`, `#2` |
| Компонент (component) | частина Compose tag після `#` (`Адреса#PbButton` → `PbButton`), інакше resource id без пакета |
| Правило елемента (element rule) | ігнорувати елемент або дозволити N% змін у ньому; для перевірки або для всього проєкту |
| Приховані зміни (invisible / semantic changes) | змінився підпис, стан або видимість, а пікселі ті самі |
| Група змін (change group) | знімки з однаковою зміною, які приймаються одним рішенням |
| Порушення, знахідка (`A11yViolation`, issue) | одна знахідка правила доступності на одному елементі одного знімка |
| Проблема (`A11yProblem`, problem) | те, на що заводиться один баг: знахідки, які налаштування вважають однаковими |
| ID проблеми (problem code) | `a11y-3f9c2a1b`; видається раз при створенні проблеми й не змінюється |
| Факти (facets) | незмінні дані про місце проблеми: правило, id елемента, компонент, екран, замір, клас, підпис |
| Замір (measure) | що виміряло правило: `38x38` (dp), `3.1` (контраст) |
| ID екрана (screen) | заголовок з UI-дерева за селекторами проєкту (`id:Appbar#Title`), інакше назва перевірки |
| Клас проблем (problem class) | правило проєкту: умови-шаблони + як групувати + заводити чи ігнорувати ([004](../specs/004-a11y-problems/spec.md)) |
| Режим дублів (duplicate mode, `groupBy`) | `component-value`, `component`, `screen`, `class` |
| Маркери (markers) | мітки Jira з фактами: `a11y-<id>`, `a11y-<правило>`, `a11y-component-…`, `a11y-value-…`, `a11y-class-…` |
| Рішення (decision) | заведено, прив'язано, знайдено в Jira, відв'язано, false positive, повернуто; пишуться в `A11yDecision` |
| «Замок» (claim) | рядок `A11yProblem` зі статусом `filing`, що не дає двом людям завести один баг одночасно |
| Задача-батько (parent task) | таска Jira, під якою заводиться баг: як підзадача або зі зв'язком |
| Особистий токен Jira | токен людини з профілю; баги заводяться від її імені ([ADR-0010](../decisions/0010-personal-jira-tokens.md)) |
