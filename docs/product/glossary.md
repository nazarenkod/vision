# Словник

Терміни upstream VRT і Vision. У коді — англійські назви з дужок. Як ці терміни звучать в
українському інтерфейсі — [глосарій перекладу](../specs/023-ukrainian-ui/design.md#глосарій-перекладу).

## Upstream VRT

| Термін | Значення |
|---|---|
| Проєкт (`Project`) | набір збірок і варіацій; у нас Android і iOS — окремі проєкти |
| Збірка (`Build`) | один прогін тестів: набір знімків |
| Знімок, прогін (`TestRun`) | результат порівняння одного скриншота з еталоном |
| Варіація (`TestVariation`) | історія еталонів для назва + гілка + OS + браузер + viewport + пристрій |
| Еталон (`Baseline`) | прийнятий скриншот; останній — очікуваний результат |
| Ігноровані області (`ignoreAreas`) | прямокутники, які не порівнюються |

## Vision

| Термін | Значення |
|---|---|
| Перевірка (check) | те, що назвав тест: назва + `customTags`. Пристрої — прогони однієї перевірки ([001](../specs/001-check-identity/spec.md)) |
| Профіль пристрою (device profile) | OS + пристрій + браузер + viewport прогону |
| Дозволений пристрій (allowed device) | пристрій + версія OS з переліку проєкту; знімки з SDK з інших пристроїв сервер відхиляє, `26.*` — будь-яка 26.x ([029](../specs/029-allowed-devices/spec.md)) |
| Еталонний пристрій (reference device) | колишнє налаштування: пристрій, з яким довідково порівнювались інші ([007](../specs/007-cross-device-reference/spec.md)); прибрано в [020](../specs/020-remove-reference-device/spec.md) |
| UI-дерево (`uiTree`) | Appium page source (XML), надісланий разом зі скриншотом |
| Елемент, ключ елемента (`nodeKey`) | `id:<resource-id або Compose tag>`, інакше `Class:текст` або `path:…`; повтори того ж id — `#1`, `#2` |
| Інтерактивний елемент (control) | вузол UI-дерева, який видно (visible, ненульові ширина й висота), увімкнений (enabled) і клікабельний (clickable), площею не більше 50 % екрана; більший — це розкладка, а не елемент керування. Його перевіряють правила доступності ([003](../specs/003-accessibility-checks/spec.md)) |
| Безіменний елемент (nameless element) | вузол UI-дерева без id, тексту й підпису; вибирається й називається в правилі селектором `xpath:` ([027](../specs/027-nameless-elements/spec.md), експеримент) |
| Опора (anchor) | стабільний елемент (з id або текстом), від якого селектор `xpath:` іде вниз до нащадка або вгору до предка ([027](../specs/027-nameless-elements/spec.md)) |
| Селектор (selector) | як правило знаходить елементи: `id:`, `class:`, `text:` (рядок або `/регулярний вираз/`), `xpath:` — шлях від опори ([ADR-0021](../decisions/0021-xpath-selectors-from-stable-elements.md)) |
| Компонент (component) | частина Compose tag після `#` (`Адреса#PbButton` → `PbButton`), інакше resource id без пакета |
| Правило елемента (element rule) | ігнорувати елемент, порівнювати лише його або дозволити N% змін у ньому; для перевірки або для всього проєкту («порівнювати лише» — тільки для перевірки) |
| Порівнювати лише (compare only) | правило, з яким у знімку перевірки порівнюються лише названі елементи, кожен із собою в еталоні, де б він не був ([015](../specs/015-compare-selected-elements/spec.md)) |
| Порівняння за одним деревом | стан «порівнювати лише», коли UI-дерево є лише в знімку або лише в еталоні: обрані елементи порівнюються на тому самому місці, без пошуку після зсуву, а знімок лишається на рев'ю ([030](../specs/030-whats-compared/spec.md)) |
| Область (ignore area, pixel area) | прямокутник VRT у пікселях знімка; запасний шлях, коли немає елемента ([024](../specs/024-elements-instead-of-areas/spec.md)) |
| Приховані зміни (invisible / semantic changes) | змінився підпис, стан або видимість, а пікселі ті самі |
| Група змін (change group) | знімки з однаковою зміною, які приймаються одним рішенням |
| Порушення, знахідка (`A11yViolation`, issue) | одна знахідка правила доступності на одному елементі одного знімка |
| Проблема (`A11yProblem`, problem) | те, на що заводиться один баг: знахідки, які правило групування вважає однаковими |
| ID проблеми (problem code) | `a11y-3f9c2a1b`; видається раз при створенні проблеми й не змінюється |
| Факти (facets) | незмінні дані про місце проблеми: правило, id елемента, компонент, екран, замір, клас, підпис |
| Замір (measure) | що виміряло правило: `38x38` (dp), `3.1` (контраст) |
| ID екрана (screen) | заголовок з UI-дерева за селекторами проєкту (`id:Appbar#Title`), інакше назва перевірки |
| Правило групування (duplicate mode) | коли знахідки — одна проблема, для кожного правила доступності: `component-value` (зона тапу, контраст), `component` (решта), `screen` (однаковий підпис); однакове для всіх проєктів ([021](../specs/021-fixed-a11y-grouping/spec.md)) |
| Маркери (markers) | мітки Jira з фактами: `a11y-<id>`, `a11y-<правило>`, `a11y-component-…`, `a11y-value-…` (`a11y-class-…` лишається на багах, заведених до [021](../specs/021-fixed-a11y-grouping/spec.md)) |
| Рішення (decision) | заведено, прив'язано, знайдено в Jira, відв'язано, false positive, повернуто; пишуться в `A11yDecision` |
| «Замок» (claim) | рядок `A11yProblem` зі статусом `filing`, що не дає двом людям завести один баг одночасно |
| Задача-батько (parent task) | таска Jira, під якою заводиться баг: як підзадача або зі зв'язком |
| Особистий токен Jira | токен людини з профілю; баги заводяться від її імені ([ADR-0010](../decisions/0010-personal-jira-tokens.md)) |
| Баг перевірки (visual bug) | баг Jira, заведений з порівняння: `[Automation] [фіча] суть`, позначений знімок і еталон; видно на всіх знімках перевірки ([025](../specs/025-bug-from-comparison/spec.md)) |
| Позначка (mark) | прямокутник або елемент UI-дерева на знімку, яким людина показує проблему; має номер |
| Назва фічі (`featureName`) | необов'язковий параметр SDK для назви бага; без нього — назва перевірки до першої крапки; не входить в ідентичність перевірки ([ADR-0019](../decisions/0019-sdk-upstream-plus-ui-tree-and-feature.md)) |
| Особистий ключ Gemini | ключ Gemini API людини з профілю, на якому AI заповнює баг; лише записується ([ADR-0020](../decisions/0020-personal-gemini-keys.md)) |
