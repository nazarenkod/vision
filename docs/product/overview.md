# Vision: огляд продукту

## Навіщо

Команди QA мобільного банкінгу (окремі проєкти для Android «AOS» та iOS) знімають скриншоти в
автотестах на Appium + Selenide. Кожен екран має еталони на емуляторі або симуляторі та на
пристрої BrowserStack. Upstream VRT порівнює лише пікселі, тож:

- рев'ю тоне в шумі: годинник у статус-барі, суми, зсув списку банером, згладжування;
- одна зміна спільного компонента дає десятки однакових карток;
- доступність не перевіряється взагалі, а якщо перевіряти, баги дублюються між екранами й людьми.

Vision додає до знімка **UI-дерево** (Appium page source) і на ньому будує все інше. Робочий VRT
тим часом лишається недоторканим.

## Для кого

| Хто | Що робить у Vision |
|---|---|
| Автоматизатор | підключає jar SDK, додає `uiTree` до наявного `track(...)` |
| QA, що рев'ює збірки | приймає або відхиляє зміни групами, заводить баги доступності в Jira |
| Ручний тестувальник | надсилає поточний екран пристрою через CLI або MCP |
| Лід / менеджер | дивиться Insights: шум, нестабільні екрани, доступність, покриття |

## Чого Vision свідомо не робить

- Не порівнює знімки різних пристроїв між собою ([ADR-0016](../decisions/0016-no-cross-device-comparison.md)).
- Не викликає LLM під час прийому знімків ([ADR-0007](../decisions/0007-deterministic-first-ai-on-demand.md)).
- Не пише в базу й файли робочого VRT ([ADR-0002](../decisions/0002-production-is-read-only.md)).
- Не перекладає дані й CLI: інтерфейс англійською або українською на вибір ([023](../specs/023-ukrainian-ui/spec.md)), а назви, id, повідомлення сервера й `vision.py` — як є.
