# Аудит безпеки й ліцензій перед перенесенням у банківський контур

Дата: 2026-11-04. Предмет: поточне дерево `main` (`5540f89`), 943 файли. У контур іде знімок без
історії, тож історію комітів тут не розбирали (окреме рішення — пізніше).

Мета — «все біле»: жодних незакритих вразливостей, компонентів без підтримки, copyleft і чужого
контенту. Окремого чек-листа ІБ банку немає, тому критерії — загальноприйняті (OWASP ASVS, OSI-ліцензії).

## Як перевіряли і чого не покриває

- Ліцензії: усі пакети з трьох `package-lock.json` (1287 + 875 + 335) звірено з `package.json`
  встановлених модулів; залежності SDK — з `build.gradle`.
- Вразливості: `npm audit` (база GitHub Advisory) окремо для прод- і dev-залежностей.
- Код: ручний розбір автентифікації, ролей на кожному ендпоінті, вхідних даних (XML, gzip, файли),
  вихідних з'єднань, зберігання секретів; grep по відомих форматах токенів, ключів, внутрішніх хостів.
- Інфраструктура: Dockerfile, docker-compose, nginx, скрипти встановлення, CI.

Не покрито (сканерів не ставили): пакети ОС усередині Docker-образів, транзитивні залежності
Gradle, автоматичний SAST, історія git. Пакети `backend/prisma` не встановлені локально — їхні
ліцензії взято з відомих даних, не з файлів. Банк, найімовірніше, прожене образи своїм сканером
(Trivy, Grype тощо) — пункти R-5 і R-10 зроблені під це.

## Знахідки безпеки

Нумерація — порядок виправлення.

### Високі

**S-1. Розбір UI-дерева: критичні CVE у парсері й gzip-бомба.**
`backend/src/ui-tree/ui-tree.parser.ts` розбирає XML, що приходить від SDK разом зі знімком,
через `fast-xml-parser` 4.5.x з `processEntities: true`. Версія має critical/high-адвайзорі
(GHSA-m7jm-9gc2-mpf2, GHSA-jmr7-xgp7-cmfj, GHSA-8gc5-j5rx-235r, GHSA-jp2q-39xq-3w4g та ін.):
розгортання сутностей у DOCTYPE без ліміту. `ui-tree.service.ts:268` робить `gunzipSync` без
`maxOutputLength`: кілька кілобайтів стиснутого запиту розгортаються в гігабайти синхронно в
event loop. Будь-хто з API-ключем (CI будь-якої команди) кладе сервер одним запитом.
Виправлення: `fast-xml-parser` ≥ 5.12, `processEntities: false` (сторінки Appium сутностей не
потребують), `gunzipSync(bytes, { maxOutputLength })`, ліміт розміру тіла.

**S-2. Персональний токен Jira можна перенаправити на чужий сервер.**
`jiraUrl` проєкту змінює будь-який editor (`PUT /projects`, перевіряється лише `@IsUrl`), а
`a11y/jira-access.ts` шле на цю адресу токен *того, хто зараз заводить баг*. Editor підставляє
свій хост — і отримує токени колег. Виправлення: список дозволених хостів Jira зі змінної
середовища (`JIRA_ALLOWED_HOSTS`), перевірка і при збереженні, і перед кожним запитом.

**S-3. Секрети користувачів у базі відкритим текстом.**
`User.jiraToken`, `User.geminiApiKey` (`prisma/schema.prisma:182–185`) зберігаються як є. API їх
не віддає (правило 7 виконане), але дамп бази, репліка чи доступ DBA = усі токени. Виправлення:
шифрування AES-256-GCM ключем із середовища; міграція додавальна (нова колонка), старі значення
переписати при старті.

### Середні

**S-4. Застосунок стартує з відомими дефолтами.** `.env` і `backend/.env` лежать у git із
`JWT_SECRET=jwtPrivateKey`, `POSTGRES_PASSWORD=postgres`, користувачем `123456` і API-ключем
`DEFAULTUSERAPIKEYTOBECHANGED` (ті самі значення — у `prisma/seed.ts` як запасні). Хто знає
дефолтний `JWT_SECRET`, підписує собі токен адміна. Виправлення: прибрати `.env` з git, лишити
`.env.example`; у проді відмовлятися стартувати з відомим `JWT_SECRET` чи паролем.

**S-5. Знімки й UI-дерева віддаються без входу.** `main.ts` віддає `imageUploads` статикою з
`Access-Control-Allow-Origin: *`, `GET /images/:fileName` теж без guard, nginx кешує їх як
`public` на рік. Імена випадкові (uuid v4), але посилання потрапляє в Jira, звіти, логи, історію
браузера — і діє назавжди. Для екранів банківського застосунку це витік. Виправлення: віддавати
через guard (JWT або підписане посилання з терміном дії), `Cache-Control: private`.

**S-6. Немає захисту від перебору й слабка парольна політика.** Ні rate limit на
`POST /users/login` і на API-ключ, ні мінімальної довжини пароля (`setPassword` перевіряє лише
непорожність). Виправлення: `@nestjs/throttler`, мінімум 12 символів, блокування після N спроб.

**S-7. Відсутні заголовки безпеки й відкритий Swagger.** Nest: `cors: true` (будь-яке
джерело), без `helmet`, `ValidationPipe` без `whitelist`. nginx: без CSP, `X-Frame-Options`,
`X-Content-Type-Options`, HSTS, `server_tokens off`. Swagger відкритий без входу.
Виправлення: CORS на `APP_FRONTEND_URL`, `helmet`, заголовки в `frontend/nginx/default.conf`,
Swagger лише за змінною середовища.

**S-8. Контейнери від root, перевірку TLS вимкнено.** Жоден Dockerfile не має `USER`.
`backend/Dockerfile:11` вимикає перевірку TLS на час `npm ci` (MITM під час збирання підмінює
пакети), а `backend/prisma/Dockerfile:9` — назавжди, бо `ENV` лишається в образі міграцій.
`test:pw:install` теж з `NODE_TLS_REJECT_UNAUTHORIZED=0`. Виправлення: `USER node`, прибрати
`NODE_TLS_REJECT_UNAUTHORIZED`, у контурі — корпоративний CA через `NODE_EXTRA_CA_CERTS`.

**S-9. Postgres опубліковано на хост.** `docker-compose.yml:93` — `${POSTGRES_PORT}:5432` на всіх
інтерфейсах. Виправлення: прибрати публікацію або `127.0.0.1:`.

### Низькі й інформаційні

- **S-10.** Кореневий `docker-compose.yml` тягне `visualregressiontracker/*` з Docker Hub —
  upstream-образи, не зібрані з цього коду; `vrt-install.sh` качає compose і `.env` з GitHub без
  перевірки. Для контуру — лише образи, зібрані з цього знімка, у внутрішньому реєстрі.
- **S-11.** Немає ізоляції між проєктами: кожен, хто увійшов, бачить усі проєкти (так в upstream).
  Якщо в одному Vision будуть різні команди чи підрядники — це питання до ІБ.
- **S-12.** OIDC має опцію `tlsNoVerify` (обмежена хостом issuer). У контурі має бути вимкнена.
- **S-13.** Frontend тримає об'єкт користувача з JWT у `localStorage` (`user.context.tsx`,
  `service.helpers.ts`): будь-який XSS забирає сесію. XSS-синків у коді немає, тож ризик низький,
  але CSP із S-7 його закриває; краще — httpOnly-кука.
- **S-14.** `bcrypt` з cost 10 — прийнятно, але сучасна рекомендація — 12.

### Знайдено пізніше

- **S-15 (середня), 2026-11-05, контрольним сценарієм.** Будь-яка помилка API (400, 401, 403,
  404, 500) повертає `stack` з абсолютними шляхами сервера й увесь об'єкт винятку
  (`backend/src/http-exception.filter.ts`, код upstream). Для Prisma-помилок це ще й деталі запиту.
  Виправлення: віддавати лише `statusCode`, `message`, `path`; stack — тільки в лог. План — 2.4.

### Що перевірено й гаразд

Ролі стоять на всіх змінювальних ендпоінтах; бекапи — лише admin (на рівні класу); Ollama —
admin/editor; відкликати посилання на звіт може лише автор чи admin; токени публічних звітів —
256 біт (`randomBytes(32)`); LDAP-фільтр екранується (RFC 2254); `GET /images/:name/download`
відсікає шляхи; у frontend немає `dangerouslySetInnerHTML` і `eval`; `UpdateUserDto` не дає змінити роль; CLI на стандартній бібліотеці з перевіркою TLS;
шрифти локальні (`@fontsource`), без Google Fonts CDN.

## Ліцензії

Власний код — Apache-2.0 (`LICENSE` у корені й пакетах, upstream VRT). Обов'язки: зберегти
`LICENSE` і копірайти upstream; за п. 4(b) змінені файли мають містити помітку про зміни —
рекомендую додати `NOTICE` у корінь: «Vision — похідна робота від Visual Regression Tracker,
© Pavel Strunkin та контриб'ютори, змінено …».

Прод-залежності — усі пермісивні:

| Ліцензія | backend | frontend | Примітка |
|---|---|---|---|
| MIT, ISC, Apache-2.0, BSD-2/3, 0BSD | 375 | 179 | — |
| BlueOak-1.0.0 | 4 | — | пермісивна, OSI |
| Python-2.0 (`argparse`) | 1 | — | пермісивна |
| MIT OR CC0-1.0 (`type-fest`) | 1 | — | — |
| OFL-1.1 (шрифти Geist, Inter, JetBrains Mono, Roboto) | — | 4 | дозволяє вбудовування |
| MIT OR GPL-3.0 (`jszip`) | — | 1 | беремо MIT, зафіксувати вибір |
| MIT AND Zlib (`pako`) | — | 1 | — |
| без поля `license` (`color-convert` 0.5.3, `pause` 0.0.1) | 2 | — | MIT за LICENSE / README |

Лише в dev (у поставку не входять): MPL-2.0 (`axe-core`, `lightningcss`, слабкий файловий
copyleft — збірку не зачіпає), CC-BY-4.0 (`caniuse-lite`, дані), Unlicense, CC0, MIT-0.

SDK: `gson` (Apache-2.0), `slf4j-api` (MIT), `lombok` (MIT, лише компіляція); тестові — Apache,
EPL-1.0 (`logback` dual EPL/LGPL — лише тести), MIT.

Мережа npm: усі `resolved` — `registry.npmjs.org`; у контурі потрібне внутрішнє дзеркало.

Що прибрати з поставки:

- **L-1. ELK-стек** (`elasticsearch/`, `kibana/`, `filebeat/`, `docker-compose*.logging.yml`):
  Elastic License 2.0 / SSPL — не OSI-ліцензії. Плюс EOL (див. вище).
- **L-2. Чужий контент у картинках.** `public/` (21 файл туторіалів upstream),
  `frontend/integration_tests/images/*`, `sdk-java/src/test/resources/home_page.png` — скриншоти
  сторінок Google з логотипами (чужі торгові марки). `public/docker_setup_creds.png` показує
  дефолтні облікові дані. Замінити власними синтетичними картинками або видалити.
- **L-3. `dist/sdk-java/*.jar`** — бінарник у репозиторії. Банк зажадає збірки з вихідних кодів:
  прибрати й збирати в контурі (`scripts/build-sdk-jar.sh`).
- **L-4. Пакети ОС в образах** (Debian/Alpine містять GPL-компоненти як окремі програми — це
  агрегація, допустимо, але сканер образів їх покаже). Перевірити сканером банку.
