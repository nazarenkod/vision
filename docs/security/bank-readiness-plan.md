# План підготовки Vision до банківського контуру

Затверджено власником 2026-11-05. Підстава — [аудит безпеки й ліцензій](audit-2026-11-04.md).

**Мета:** Vision проходить сканер вразливостей і ліцензій без знахідок; кожен бачить лише свої
проєкти; вхід через корпоративний LDAP/SSO і локальні акаунти разом; продукт виглядає як власний
(VRT лишається лише в `LICENSE` і `NOTICE`, як вимагає Apache-2.0); усе, що працює зараз, працює й
після переходу — і це доводять тести.

**Як працюємо:** кожна задача — окрема гілка від свіжого `main`; зміна поведінки — зі
специфікацією й тестами в одному коміті; після кожної задачі — `/verify` і
[контрольний сценарій](../guides/testing.md#контрольний-сценарій); пуш — лише з дозволу власника.

## Перехід на нову версію

1. Зупинити старий Vision.
2. Скрипт конвертує `.env`: `VRT_*` → `VISION_*`, ключ шифрування, хости Jira, нові секрети JWT;
   показує, що змінилось.
3. Скопіювати базу й знімки робочого VRT, як зараз (`demo-clone-from-prod.sh`, VRT лише читається).
4. Запустити нову версію. На першому старті: додавальні міграції поверх схеми VRT, усім — доступ до
   всіх проєктів, секрети шифруються, API-ключі з копії VRT анулюються.
5. Перевірка: контрольний сценарій лише на читання, звірка кількостей проєктів, збірок, знімків і
   користувачів з VRT.
6. Кожен генерує новий API-ключ у профілі й оновлює його в CI; тестові проєкти — на новий jar SDK.
7. Відкат: зупинити нову версію, знову скопіювати VRT, запустити стару.

Для людей: усі заново входять, новий API-ключ і jar SDK. Як і зараз, те, що створено лише у Vision,
після копіювання з VRT починається з нуля.

## Хвиля 0. Зафіксувати поточну поведінку

- **0.1** Контрольний сценарій через API: SDK зі знімками й UI-деревами → порівняння, approve,
  reject, undo → ignore-areas і правила елементів → доступність → баги в Jira (мок) → посилання на
  звіт → Insights → CLI і MCP → знімки → ролі. Еталон знято на `main`.
- **0.2** Тести запобіжників і скрипта копіювання: робочий VRT лише читається.

## Хвиля 1. Виправлення, оновлення, ребрендинг

- **1.1 Реліз SDK і захист від великих дерев** (специфікація). Сервер: `fast-xml-parser` ≥ 5.12
  без розгортання сутностей, ліміти gzip і тіла; дерево понад ліміт відкидається, знімок
  приймається. SDK: той самий ліміт, завелике дерево не надсилається (попередження в лог); новий
  Java-пакет і Maven-координати, класи `Vision*` лишаються, запити до сервера не змінюються.
- **1.2 Мажорні оновлення backend.** Nest 12, Prisma 7; свіжі `swagger`, `rimraf`, `ldapts`;
  `uuid-apikey` → `crypto.randomUUID`; `react-joyride` 3; eslint 9, jest 30. Перевірка: тести
  хвилі 0 зелені, міграції лягають на копію бази VRT, схема без змін, `npm audit` = 0.
- **1.3 Образи й інфраструктура.** Node 24 LTS, stable nginx, Postgres 16; `USER node`, образи за
  digest; без вимкнення TLS (CA — `NODE_EXTRA_CA_CERTS`, реєстр npm — build arg); Postgres не на
  хост; compose збирає з цього коду; телеметрія Scarf і Prisma вимкнена.
- **1.4 Чистота поставки.** Прибрати ELK, `public/` з туторіалами upstream, скриншоти Google
  (тестові картинки — синтетичні), jar з `dist/`; `.env` з git → `.env.example`.
- **1.5 Ребрендинг.** Пакети, змінні `VISION_*`, образи, compose-проєкт і назва бази → `vision`
  (`PROD_*` — джерело копіювання — лишаються); прибрати старі workflow upstream,
  `.all-contributorsrc`, контриб'юторів у README, `vrt-install.sh`; README переписати; `NOTICE` з
  атрибуцією VRT; новий ADR замість ADR-0001.

## Хвиля 2. Нова поведінка (кожна — специфікація)

- **2.1 Ізоляція проєктів.** Таблиця «користувач ↔ проєкт»; адмін бачить усе й роздає доступ;
  editor, що створив проєкт, отримує доступ; перевірка на кожному запиті, зокрема через API-ключ і
  в socket-подіях; на першому старті всі отримують доступ до всіх проєктів.
- **2.2 Знімки лише з входом або за підписаним посиланням** з терміном дії; знімки на диску, як і
  зараз; публічні звіти — за своїм токеном.
- **2.3 Секрети.** Токени Jira і ключі Gemini шифруються в базі; Jira — лише хости зі списку; у
  базі лише хеш API-ключа, повний показується раз; ключі з копії VRT анулюються.
- **2.4 Захист API.** `helmet` і заголовки безпеки в nginx; CORS лише для свого frontend; Swagger
  за прапорцем; помилки без stack trace і внутрішнього об'єкта винятку (S-15 аудиту).
- **2.5 Корпоративний вхід і локальні акаунти разом.** LDAP або OIDC/SSO і локальні акаунти від
  адміна; обмеження спроб входу для обох; вимоги до пароля — лише для локальних. Compose зараз передає
  в API лише `OIDC_ENABLED` і `LDAP_ENABLED` — решту налаштувань `LDAP_*` / `OIDC_*` теж треба передати.

## Хвиля 3. Універсальність і перехід

- **3.1** Агентське оточення без прив'язки до конкретного репозиторію: remote і правила пушу — з
  конфігурації.
- **3.2** Нейтральні домени замість доменів банку в тестах і специфікаціях.
- **3.3** Документація без «upstream».
- **3.4** Скрипти переходу: конвертація `.env`, перевірка після запуску зі звіркою з VRT; тести.
- **3.5** Репетиція переходу на копії: стара версія → конвертація → копія VRT → нова версія →
  контрольний сценарій → звірка → відкат; інструкція переходу для контуру.
- **3.6** Скрипт експорту знімка без історії — запуск лише за окремим рішенням власника.

## Лишається як є

Бекапи (разом із Google Drive; ризик — у аудиті), знімки на диску.

## Відкладено

S3, React 19 / MUI 7 / DataGrid 8, переписування SDK з нуля. Сесія в httpOnly-куці — прибрано.

## Фінальна перевірка

`npm audit` = 0 в усіх пакетах; повторний підрахунок ліцензій; grep на секрети, домени й назву
VRT (лише `LICENSE` і `NOTICE`); контрольний сценарій зелений; репетиція переходу пройдена.
Образи Docker сканером — лише з дозволу власника або в банку.
