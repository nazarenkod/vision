# Безпека: огляд

Коротко про те, які дані обробляє Vision, як вони захищені, що перевірено і які ризики лишаються.
Для служби інформаційної безпеки й архітекторів. Деталі — у специфікаціях, на які посилаються рядки.

## Дані

| Дані | Де | Чутливість |
|---|---|---|
| Знімки екранів мобільних і вебзастосунків | файли в `demo-data/imageUploads` | **висока**: можуть містити ПІБ, номери карток і рахунків, баланси тестових клієнтів |
| UI-дерева екранів (XML/HTML з текстами) | там само, `.uitree.json.gz` | висока, як знімки |
| Звіти доступності, рішення команди, правила | Postgres і файли | низька |
| Користувачі: email, ім'я, роль, хеш пароля (bcrypt) | Postgres | персональні дані співробітників |
| API-ключі | Postgres, лише SHA-256 | секрет |
| Токени Jira, ключі Gemini | Postgres, AES-256-GCM ключем `VISION_SECRET_KEY` | секрет |

**Рекомендація:** автотести мають працювати на тестових даних, а не на даних реальних клієнтів.
Знімки й дерева зберігаються, доки існує збірка: видаляються разом зі збіркою в інтерфейсі.

## Автентифікація

- Локальні акаунти створює лише адміністратор; самореєстрації немає ([035](../specs/035-admin-accounts/spec.md)).
- LDAP/AD або SSO (OIDC) поруч із локальними акаунтами ([045](../specs/045-sign-in-and-api-hardening/spec.md)).
- Пароль локального акаунта — від 12 символів, bcrypt; 5 невдалих спроб поспіль — вхід для email
  закрито на 15 хвилин (і для LDAP).
- Сеанс — JWT, підписаний `JWT_SECRET` (≥ 32 символів, API не стартує зі слабким); діє `JWT_LIFE_TIME`
  (типово 1 день). «Вийти» анулює токен на сервері; зміна пароля завершує інші входи
  ([052](../specs/052-sessions-and-browser-hardening/spec.md)).
- CI і CLI — особистий API-ключ людини; показується один раз, у базі — лише хеш
  ([044](../specs/044-secrets-at-rest/spec.md)).
- WebSocket подій — лише з JWT і лише для проєктів, до яких є доступ ([032](../specs/032-authenticated-events/spec.md)).

## Авторизація

- Ролі `admin`, `editor`, `guest` перевіряються на кожному маршруті, що змінює дані.
- Доступ до проєктів: користувач і його API-ключ бачать лише свої проєкти; чужий проєкт — `404`
  ([042](../specs/042-project-access/spec.md)).
- Знімки видаються лише за HMAC-підписом, який отримує той, хто має доступ до проєкту; прямих
  шляхів до файлів немає ([043](../specs/043-protected-images/spec.md)).
- Публічні звіти збірки — лише за окремим токеном, який створює людина з доступом
  ([ADR-0022](../decisions/0022-public-report-links.md)).

## Мережа й платформа

- Postgres не публікується на хост; назовні лише порти `ui` і `api`.
- Контейнери не від root; базові образи закріплені за digest; TLS під час збирання не вимикається.
- Заголовки: CSP (скрипти лише з Vision), `X-Frame-Options: DENY`, `X-Content-Type-Options: nosniff`,
  `Referrer-Policy: no-referrer`, HSTS за HTTPS-проксі; `server_tokens off`.
- CORS — лише origin інтерфейсу (`DEMO_UI_URL`); Swagger вимкнено (`VISION_SWAGGER=false`).
- Помилки — без stack trace і внутрішніх об'єктів.
- Ліміти: знімок ≤ 50 МБ і 40 Мпікс, UI-дерево ≤ 10 МиБ після розпакування, XML без сутностей
  ([040](../specs/040-uitree-limits-and-sdk-names/spec.md)).
- Jira — лише хости з `VISION_JIRA_HOSTS`, лише `https`, без переадресацій.
- LLM не викликається під час прийому знімків; лише на вимогу людини і лише якщо увімкнено
  ([ADR-0007](../decisions/0007-deterministic-first-ai-on-demand.md)).
- Телеметрія збирання вимкнена; вихідні з'єднання — лише перелічені у [вимогах](../admin/requirements.md#вихідні-з-сервера).

## Залишкові ризики

| Ризик | Рівень | Що робити |
|---|---|---|
| Vision слухає HTTP | середній | TLS на зворотному проксі, `X-Forwarded-Proto: https`; порти `ui`/`api` закрити від усього, крім проксі |
| Перший адміністратор з паролем `123456`, якщо не задано `DEFAULT_USER_PASSWORD` | середній | задати пароль до першого запуску або змінити одразу |
| Сеанс у `localStorage`, а не в httpOnly-куці (S-13) | низький | компенсується CSP без inline-скриптів і анулюванням на сервері; рішення власника — відкладено |
| bcrypt cost 10 (S-14) | низький | прийнято; підвищення — окремою задачею |
| `OIDC_TLS_NO_VERIFY`, `LDAP_TLS_NO_VERIFY` існують (S-12) | низький | лишати `false`; контролювати конфігурацію |
| Бекапи не шифруються; Google Drive як місце бекапів | **високий, якщо Drive** | внутрішнє сховище (`BACKUP_REMOTE`), шифрування на боці сховища |
| Gemini отримує знімки, якщо `AI_PROVIDER=gemini` | високий, якщо увімкнено | лишити `none` або `ollama` у своїй мережі |
| Немає журналу аудиту дій адміністратора (окрім журналу рішень рев'ю) | низький | логи API в системі збору логів |
| `VISION_SECRET_KEY` — один ключ без ротації | середній | зберігати в сховищі секретів, доступ лише адміністраторам |
