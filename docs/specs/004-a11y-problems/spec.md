# 004 — Проблеми доступності: ID, факти, класи, без дублів

- **Статус:** Implemented (реальна Jira Cloud ще не перевірена)
- **Оновлено:** 2026-10-27
- **Пов'язане:** [003](../003-accessibility-checks/spec.md) (звідки беруться знахідки),
  [005](../005-jira-bugs/spec.md) (як заводиться баг), [ADR-0008](../../decisions/0008-stable-problem-ids-from-facts.md),
  [ADR-0009](../../decisions/0009-jira-mirrors-local-decisions.md)
- **Код:** `backend/src/a11y/a11y-problems.ts` (ідентичність, класи, маркери), `a11y-issues.ts`
  (рев'ю), `a11y-issues.service.ts` (рішення, «замок», Jira), `frontend/…/InsightsPanel.tsx`,
  `frontend/…/ProjectForm/A11yProblemSettings.tsx`

## Проблема

- Одна й та сама проблема компонента (кнопка `PbButton` 38×38 dp) видна на десятках екранів, і
  без групування на кожен екран заводився б окремий баг.
- Кілька людей рев'юють одночасно, тож без захисту один баг заведуть двічі.
- Команда налаштовує, що вважати однією проблемою. Якби ID залежав від налаштувань, кожна їхня
  зміна відривала б заведені баги.
- Баги заводять і руками, і з інших інсталяцій, тож без пошуку в Jira їх не знайти.
- Якщо баг відв'язали в Vision, автоматичний пошук не повинен прив'язати його знову.

## Цілі й межі

- **Ціль:** один баг на одну проблему, хоч скільки екранів, людей і змін налаштувань.
- **Не входить:** синхронізація статусу бага з Jira (закрито → перевідкрити); групування знахідок
  різних правил в одну проблему.

## Модель

- **Знахідка** (violation) — правило + елемент на одному знімку ([003](../003-accessibility-checks/spec.md)).
- **Факти** знахідки: правило, id елемента (resource id або Compose tag без `#N`), компонент
  (частина tag після `#`, інакше resource id без пакета), екран (заголовок за селекторами
  проєкту, інакше назва перевірки), замір (`38x38`, `3.1`), клас і підпис елемента. Від
  налаштувань факти не залежать.
- **Ключ проблеми** — функція `problemKeyOf(факти, налаштування)`. Його перераховують щоразу, і для
  нових знахідок, і для фактів збережених проблем.
- **Проблема** (`A11yProblem`) — ID (`a11y-` + 8 hex; видається раз), факти місць, статус
  (`filing` / `reported` / `ignored`), баг.

## Критерії приймання

1. Дано знімки «Адреси» і «Платежі» з однаковою таб-панеллю (вкладки 38×38 dp) і клас «Tab bar»
   з умовою `/^.*:id\/(tab)_\d+$/`. Коли заводять баг з «Платежі», тоді «Адреси» показує ту саму
   проблему з тим самим ID як заведену.
2. Коли клас видаляють, тоді на «Адреси» кожна вкладка — окрема картка, але з тим самим ID і
   багом.
3. Коли двоє одночасно натискають «Create bug», тоді в Jira з'являється один баг, а другий
   отримує «вже заведено як KEY».
4. Коли баг відв'язують, тоді в Jira з нього зникають мітки Vision і з'являється
   `a11y-unlinked-…`, а наступне відкриття рев'ю не прив'язує його знову.

## Відомі обмеження

- Проблеми без фактів (створені до 2026-10-26) мають факти лише рівня компонента з ключа.
- Баг, заведений руками, знаходиться, лише якщо на ньому є ID або повний набір маркерів.
- Пошук під час рев'ю йде під токеном того, хто дивиться; без особистого чи спільного токена
  його немає.
