# 005 — Баги в Jira

- **Статус:** Implemented (перевірено на фейкових Jira DC 9 і Cloud; реальна `privatbank.atlassian.net` — ще ні)
- **Оновлено:** 2026-10-27
- **Пов'язане:** [004](../004-a11y-problems/spec.md) (що саме заводиться й коли — дубль),
  [ADR-0010](../../decisions/0010-personal-jira-tokens.md)
- **Код:** `backend/src/a11y/jira.client.ts`, `jira-bug.ts` (текст і поля), `a11y-issues.service.ts`
  (`prepareBug`, `fileBug`), `frontend/…/JiraBugDialog.tsx`, `JiraFieldInput.tsx`, `components/JiraTokenCard.tsx`

## Проблема

Команда заводить баги регресу як **підзадачі** («Помилка») під таскою регресу. На екрані
створення є обов'язкові поля (серйозність, «Замовник»), а опис має фіксований шаблон.
Заводити руками з картинкою й описом довго, і без шаблону виходять різні баги.

## Вимоги

### Доступ

| ID | Вимога |
|---|---|
| REQ-005-01 | СИСТЕМА ПОВИННА звертатися до Jira за URL з налаштувань проєкту й з особистим токеном того, хто діє (Server/DC — PAT як Bearer, Cloud — email + API token), а якщо його немає — зі спільним токеном проєкту. |
| REQ-005-02 | ЯКЩО немає ні особистого, ні спільного токена, ТО СИСТЕМА ПОВИННА сказати додати токен у профілі. |
| REQ-005-03 | СИСТЕМА ПОВИННА ніколи не повертати токени через API (лише `jiraTokenSet`). |

### Підготовка

| ID | Вимога |
|---|---|
| REQ-005-10 | КОЛИ вказано ключ таски, СИСТЕМА ПОВИННА прочитати таску та отримати з її проєкту типи задач, поля екрана створення й типи зв'язків. Підтримуються формати Jira 9 / DC (`values`), Cloud (`issueTypes`/`fields` з пагінацією) і старий createmeta (Jira 8). |
| REQ-005-11 | СИСТЕМА ПОВИННА пропонувати тип задачі в такому порядку: налаштований у проєкті → підзадача-баг → баг → будь-яка підзадача; у браузері запам'ятовувати, які типи й зв'язки людина вибирає найчастіше. |
| REQ-005-12 | ДЕ тип задачі — підзадача, СИСТЕМА ПОВИННА заводити баг підзадачею таски; інакше — окремою задачею зі зв'язком вибраного типу (налаштований → «Relates» / «пов'язано» → перший). |
| REQ-005-13 | СИСТЕМА ПОВИННА призначати баг виконавцю таски: через поле екрана створення, а якщо його немає — окремим викликом після створення. |
| REQ-005-14 | СИСТЕМА ПОВИННА ставити серйозність **S4** у поле, що називається «Серйозність помилки» / Severity. |
| REQ-005-15 | СИСТЕМА ПОВИННА копіювати з таски «Замовника» та інші обов'язкові поля, які в неї заповнені; серйозність, «Замовника» й незаповнені обов'язкові поля показувати в діалозі (людей — пошуком у Jira, варіанти — списком) і запам'ятовувати вибір для проєкту. |
| REQ-005-16 | ЯКЩО Jira вимагає поле, яке діалог не вміє заповнити, ТО СИСТЕМА ПОВИННА назвати його й не давати створити баг. |
| REQ-005-17 | СИСТЕМА ПОВИННА надсилати лише поля, що є на екрані створення вибраного типу. |
| REQ-005-18 | СИСТЕМА ПОВИННА запам'ятовувати таску для екрана (у браузері) і підставляти її наступного разу. |

| REQ-005-22 | КОЛИ проблема охоплює кілька елементів, СИСТЕМА ПОВИННА перелічити їх у фактичному результаті й обвести всі на скриншоті. |
| REQ-005-23 | СИСТЕМА ПОВИННА прикладати скриншот з обведеними елементами. |
| REQ-005-24 | ЯКЩО зв'язок, призначення, вкладення чи мітки не вдалися, ТО СИСТЕМА ПОВИННА лишити баг створеним і повернути попередження. |
