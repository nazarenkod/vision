## Контекст і проблема

AI корисний, щоб пояснити групу змін і запропонувати підписи для іконок. Але платні виклики на
кожен знімок дорогі, а локальна модель (Mac Studio M2) мусить бути легкою.

## Користувацькі історії

### US-1 (P2): Пояснення групи змін

Як QA, я хочу одним кліком отримати короткий опис того, що змінилось у групі, і чи схоже це на
задум, регресію чи шум, щоб швидше вирішити.

### US-2 (P2): Підписи для іконок

Як QA, я хочу отримати пропозицію підпису для іконки без підпису, щоб додати її в баг.

### US-3 (P1): Контрольовані витрати

Як власник продукту, я хочу, щоб AI нічого не коштував, поки ним не користуються, і мав денний
ліміт, щоб витрати були передбачуваними.

## Вимоги

| ID | Історія | Вимога |
|---|---|---|
| REQ-010-01 | US-3 | СИСТЕМА ПОВИННА вимикати AI й ховати його в інтерфейсі, поки не задано провайдера (Gemini або локальну Ollama) і його облікові дані. |
| REQ-010-02 | US-3 | СИСТЕМА ПОВИННА звертатися до моделі лише на прохання людини в рев'ю і ніколи — під час прийому знімка. |
| REQ-010-03 | US-1 | СИСТЕМА ПОВИННА робити один запит на групу змін, а не на знімок. |
| REQ-010-08 | US-3 | СИСТЕМА ПОВИННА надсилати лише текст, коли зміну пояснює UI-дерево, а інакше — дві невеликі вирізки навколо змін. |
| REQ-010-04 | US-3 | СИСТЕМА ПОВИННА пояснювати групи шуму правилами, без моделі. |
| REQ-010-05 | US-3 | СИСТЕМА ПОВИННА повторно використовувати відповідь на той самий запит і питати знову лише тоді, коли змінились картинки. |
| REQ-010-06 | US-3 | СИСТЕМА ПОВИННА зупиняти платні запити на денному ліміті (типово 500). |
| REQ-010-07 | US-2 | СИСТЕМА ПОВИННА пропонувати підписи для іконок без підпису мовою текстів самого екрана. |
