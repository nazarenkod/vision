# 011 — Розгортання поруч із продом

- **Статус:** Implemented
- **Оновлено:** 2026-10-27
- **Пов'язане:** [ADR-0002](../../decisions/0002-production-is-read-only.md), [DEPLOY.md](../../../DEPLOY.md)
- **Код:** `scripts/vision.sh`, `scripts/lib/vision-safety.sh`, `scripts/demo-clone-from-prod.sh`,
  `docker-compose.demo.yml`, `.env.demo.example`

## Проблема

Vision ставиться на ту саму машину, що й робочий VRT, і копіює його дані. Помилка в імені
compose-проєкту, заповнений диск чи запис у чужий контейнер зачепили б прод.

## Вимоги

| ID | Вимога |
|---|---|
| REQ-011-01 | СИСТЕМА ПОВИННА виконувати команди compose лише для проєкту `vision`, зашитого в скрипт, ігноруючи `COMPOSE_PROJECT_NAME` з оточення. |
| REQ-011-02 | ЯКЩО в проєкті `vision` є контейнер, створений не з `docker-compose.demo.yml` цього репозиторію, ТО СИСТЕМА ПОВИННА нічого не робити. |
| REQ-011-03 | Копіювання СИСТЕМА ПОВИННА робити лише читанням проду: `pg_dump` у транзакції тільки для читання з `nice 19`, кілька `SELECT` для перевірок, копія або жорсткі посилання на файли без відкриття на запис. |
| REQ-011-04 | СИСТЕМА ПОВИННА очищати й відновлювати базу лише в контейнері, перевіреному як власний Postgres Vision, і відмовляти, якщо `PROD_PG_CONTAINER` вказує на контейнер Vision, а `PROD_IMAGES_DIR` — на папку Vision. |
| REQ-011-05 | Перед копіюванням і збиранням СИСТЕМА ПОВИННА перевіряти, що після операції на диску лишиться щонайменше 10 ГБ або 5% (що більше; `VISION_DISK_RESERVE_GB`). |
| REQ-011-06 | СИСТЕМА ПОВИННА обмежувати ресурси Vision: API — 2 CPU / 3 ГБ, 2 потоки порівняння, Postgres — 1 CPU / 1 ГБ, UI — 0,5 CPU (налаштовується). |
| REQ-011-07 | Перед копіюванням СИСТЕМА ПОВИННА показувати, що буде прочитано й замінено, і чекати `yes`. |
| REQ-011-08 | Після копіювання СИСТЕМА ПОВИННА застосовувати до копії міграції Vision (і новіші за upstream), не торкаючись проду. |
