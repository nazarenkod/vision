## Контекст і проблема

Vision ставиться на ту саму машину, що й робочий VRT, і працює на копії його даних. Помилка в
назві проєкту docker compose, заповнений диск, запис у чужий контейнер чи забрані в проду CPU й пам'ять
зачепили б прод, а пошкодити прод не можна за жодних умов.

## Користувацькі історії

### US-1 (P1): Розгорнути без ризику для проду

Як людина, що розгортає Vision, я хочу, щоб будь-яка моя помилка в командах зупинялась до того,
як вона торкнеться проду.

- **Незалежна перевірка:** зняти «відбиток» проду, виконати всі кроки розгортання й навмисні
  помилки, зняти відбиток знову.
- **Сценарії приймання:**
  1. **Дано** контейнер проду в проєкті з тим самим ім'ям, **коли** запускають будь-яку команду
     Vision, **тоді** нічого не відбувається, а людина бачить причину.
  2. **Дано** диск, на якому лишиться менше запасу, **коли** запускають копіювання, **тоді** воно
     не починається.

### US-2 (P1): Копія даних проду

Як людина, що розгортає Vision, я хочу отримати копію бази й картинок проду однією командою з
підтвердженням, щоб Vision показував реальні дані.

## Вимоги

| ID | Історія | Вимога |
|---|---|---|
| REQ-011-01 | US-1 | СИСТЕМА ПОВИННА виконувати команди docker compose лише для проєкту `vision`, заданого в скрипті, ігноруючи назву проєкту з оточення. |
| REQ-011-02 | US-1 | ЯКЩО в проєкті `vision` є контейнер, створений не з compose-файлу Vision цього репозиторію, ТО СИСТЕМА ПОВИННА нічого не робити й пояснити чому. |
| REQ-011-03 | US-2 | СИСТЕМА ПОВИННА лише читати прод: дамп бази в транзакції для читання з найнижчим пріоритетом CPU, кілька запитів для перевірок, копіювання файлів (або жорсткі посилання) без відкриття на запис. |
| REQ-011-04 | US-1 | СИСТЕМА ПОВИННА очищати й відновлювати базу лише в контейнері, перевіреному як власна база Vision. |
| REQ-011-09 | US-1 | ЯКЩО налаштування джерела копії вказують на контейнер або папку самого Vision, ТО СИСТЕМА ПОВИННА відмовитися копіювати. |
| REQ-011-05 | US-1 | Перед копіюванням і збиранням образів СИСТЕМА ПОВИННА перевіряти, що на диску лишиться щонайменше 10 ГБ або 5% (що більше; налаштовується). |
| REQ-011-06 | US-1 | СИСТЕМА ПОВИННА обмежувати CPU й пам'ять, які забирає Vision (типово: API — 2 CPU і 3 ГБ, 2 потоки порівняння, база — 1 CPU і 1 ГБ, UI — 0,5 CPU). |
| REQ-011-07 | US-2 | Перед копіюванням СИСТЕМА ПОВИННА показати, що буде прочитано й замінено, і чекати підтвердження `yes`. |
| REQ-011-08 | US-2 | ЯКЩО база проду старша за VRT 5.x, ТО СИСТЕМА ПОВИННА зупинити копіювання й порадити спершу оновити прод або почати з порожньої бази. |
| REQ-011-10 | US-2 | КОЛИ Vision стартує на копії, СИСТЕМА ПОВИННА застосувати міграції Vision до копії. |
| REQ-011-11 | US-2 | ЯКЩО обрано жорсткі посилання на картинки, а дані Vision лежать на іншому диску, ніж картинки проду, ТО СИСТЕМА ПОВИННА зупинитися й порадити копіювання. |

## Граничні випадки

- У shell виставлено `COMPOSE_PROJECT_NAME` прод-проєкту → ігнорується (REQ-011-01).
- Обрано жорсткі посилання, а дані Vision на іншому диску → зупинка з порадою копіювати або перенести репозиторій (REQ-011-11).
- Для копії картинок не вистачає місця → зупинка з порадою режиму посилань (REQ-011-05).
