## Контекст і проблема

Правила елементів уміють лише прибирати з порівняння: ігнорувати елемент або допускати в ньому
N% змін. Коли тест перевіряє один компонент (кнопку оплати, картку товару, тулбар) на екрані,
де решта динамічна (стрічка, банери, рекомендації), доводиться перелічувати все, що треба
ігнорувати, і цей перелік ламається з кожною новою секцією екрана. Простіше назвати те, що
перевіряємо, ніж усе, що ні.

## Користувацькі історії

### US-1 (P1): Порівнювати лише названі елементи

Як QA, я хочу задати для перевірки елементи, які порівнюються, щоб зміни поза ними не давали
рев'ю.

- **Чому P1:** це і є фіча.
- **Незалежна перевірка:** для перевірки задати «порівнювати лише `id:btn_pay`», змінити банер
  над кнопкою → знімок збігається; змінити колір кнопки → знімок на рев'ю.
- **Сценарії приймання:**
  1. **Дано** правило «порівнювати лише `id:btn_pay`», **коли** змінилась лише стрічка над
     кнопкою, **тоді** знімок збігається.
  2. **Дано** те саме правило, **коли** змінився підпис кнопки, **тоді** знімок на рев'ю, а
     зміна показана на кнопці.
  3. **Дано** те саме правило, **коли** кнопки немає в новому знімку, **тоді** знімок на рев'ю
     з повідомленням, що обраний елемент зник.

### US-2 (P1): Елемент порівнюється сам із собою, де б він не був

Як QA, я хочу, щоб обраний елемент порівнювався зі своєю копією в еталоні навіть після зсуву,
щоб банер, що відсунув кнопку, не давав зміни.

- **Чому P1:** без цього будь-яка зміна вище на екрані зсуває елемент і дає рев'ю, і користі
  від фічі майже немає.
- **Незалежна перевірка:** кнопка зсунулась на 100 px через новий банер, сама не змінилась →
  знімок збігається.

### US-3 (P2): Обрати елемент кліком

Як QA, я хочу обрати елемент для порівняння кліком по скриншоту, як для правила «ігнорувати».

- **Незалежна перевірка:** Changes → вибір елемента на скриншоті → «Compare only this» → правило
  з селектором елемента для цієї перевірки.

## Граничні випадки

- Банер зсунув обрану кнопку, кнопка та сама → збіг (REQ-015-11).
- Кнопка стала ширшою → зміна (REQ-015-12).
- Усередині обраної картки є годинник під правилом «ігнорувати» → годинник не рахується (REQ-015-13).
- Три картки з одним id в еталоні, дві в знімку → зміна (REQ-015-14).
- Опечатка в селекторі, нічого не збіглось → рев'ю з повідомленням, а не тихий «збіг» (REQ-015-21).
- Поза обраними елементами кнопка стала вимкненою → не зміна (REQ-015-10).

## Ключові сутності

- **Правило «порівнювати лише»** — селектор, область дії (перевірка), примітка; новий вид правила
  елемента поряд з «ігнорувати» й «допуск N%».

## Критерії успіху

| ID | Критерій |
|---|---|
| SC-015-01 | Зміни поза обраними елементами дають 0 знімків на рев'ю для перевірок з правилом «порівнювати лише». |
| SC-015-02 | 0 знімків з правилом, яке нічого не знайшло, позначаються як збіг. |

## Припущення

- «Порівнювати між собою» означає обраний елемент у знімку проти того самого елемента в еталоні
  тієї самої перевірки й пристрою, а не різні елементи чи пристрої між собою.
- Обрані елементи мають стабільні селектори (ідентифікатор ресурсу або Compose tag).

## Поза межами

- Порівняння обраного елемента між різними пристроями (для цього є 007).
- Порівняння двох різних елементів одного екрана між собою.
- Обрані області без UI-дерева (довільні прямокутники): для цього є ігноровані області VRT.
