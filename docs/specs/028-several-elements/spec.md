## Контекст і проблема

У режимі «Select elements» можна додати до обраного ще елементи, клацаючи їх із затиснутим
Shift (REQ-024-05). Дія тоді створює по правилу на кожен обраний елемент. Але цим майже ніхто
не користується, бо:

- про Shift ніде не сказано: ні в підказці, ні в діях біля елемента;
- видно лише «3 selected» у діях біля останнього клікнутого елемента. Які саме елементи обрано,
  не видно, і прибрати один із вибору можна лише повторним Shift + клік по ньому;
- дії стоять біля останнього кліку й закривають сусідні елементи, які теж хочеться обрати;
- «Parent» (↑) скидає вибір до одного елемента без попередження;
- якщо один з обраних уже має правило, про це не сказано, а дія створює для нього ще одне.

Тож QA, якому треба проігнорувати годинник, таймер і банер, робить це тричі по одному.

## Користувацькі історії

### US-1 (P1): Обрати кілька елементів і бачити, які саме

Як QA, я хочу обрати на знімку два-три елементи й бачити, які саме обрано, щоб дати їм одну дію,
а не повторювати її для кожного.

- **Чому P1:** без видимого вибору решта фічі не має сенсу.
- **Незалежна перевірка:** «Select elements» → клік по таймеру → «Add more elements» → клік по
  бейджу → під знімками панель «2 elements selected» з елементами 1 і 2. На еталоні й знімку біля
  таймера й бейджа рамки з тими самими номерами.
- **Сценарії приймання:**
  1. **Дано** обрано один елемент, **коли** QA дивиться на дії біля нього, **тоді** бачить «Add
     more elements» і підказку, що те саме робить Shift + клік.
  2. **Дано** обрано один елемент, **коли** QA клікає інший із Shift, **тоді** під знімками
     відкривається панель вибору з двома елементами, а дії біля елемента закриваються.
  3. **Дано** відкрита панель вибору, **коли** QA клікає третій елемент без Shift, **тоді** він
     додається з номером 3.
  4. **Дано** обрано три елементи, **коли** QA клікає четвертий, **тоді** його не додано, а панель
     каже, що можна обрати не більше трьох.
  5. **Дано** обрано два елементи на знімку, **коли** QA клікає елемент на еталоні, **тоді** вибір
     починається знову з цього елемента.
  6. **Дано** обрано три елементи, **коли** QA натискає × біля другого, **тоді** його немає ні в
     панелі, ні на знімках, а решта перенумеровані 1 і 2.

### US-2 (P1): Одна дія для всіх обраних

Як QA, я хочу проігнорувати, порівнювати лише чи дозволити зміни в усіх обраних елементах одним
натисканням і так само одним Undo скасувати, щоб не робити це тричі.

- **Чому P1:** заради цього й обирають кілька.
- **Незалежна перевірка:** обрати годинник, таймер і банер → Ignore → три правила в «What's
  compared», одне сповіщення «3 rules added» з Undo → Undo → правил немає, знімок порівняно
  знову.
- **Сценарії приймання:**
  1. **Дано** обрано три елементи без правил, **коли** QA натискає I, **тоді** зберігаються три
     правила «ігнорувати» для цього екрана, знімок порівнюється знову, і є одне сповіщення з Undo.
  2. **Дано** щойно додано три правила, **коли** QA натискає Undo, **тоді** немає жодного з трьох.
  3. **Дано** обрано два елементи, **коли** QA обирає All screens, **тоді** Compare only
     недоступне з поясненням, як для одного елемента.
  4. **Дано** дію виконано, **коли** QA дивиться на знімок, **тоді** вибір порожній, а режим
     «Select elements» лишається ввімкненим.

### US-3 (P2): Обрані елементи, що вже мають правило

Як QA, я хочу бачити, що один з обраних уже має правило, щоб дія не створювала дублів і не
змінювала його непомітно.

- **Незалежна перевірка:** годинник уже ігнорується на всіх екранах; обрати годинник і банер →
  годинник у панелі позначений «Ignored», панель каже, що його пропущено → Compare only →
  правило лише для банера, правило годинника без змін.
- **Сценарії приймання:**
  1. **Дано** серед обраних один має правило, **коли** QA обирає дію, **тоді** правило
     створюється лише для інших, а правило цього елемента не змінюється.
  2. **Дано** усі обрані ігноруються, **коли** QA дивиться на панель, **тоді** замість дій бачить
     «Remove 2 rules».
  3. **Дано** серед правил, що видаляються, є правило для всіх екранів, **коли** QA натискає
     «Remove 2 rules», **тоді** перед видаленням його питають підтвердження.

## Граничні випадки

- Два обрані елементи знаходить той самий селектор (дві картки `id:offer_card`) → одне правило,
  у сповіщенні «1 rule added» (REQ-028-20).
- Обрано три, один прибрали → можна додати ще один (REQ-028-05, 13).
- Обрано два, QA натискає ↑ → нічого: ↑ працює лише для одного (REQ-028-15).
- Обраний безіменний елемент має кілька способів знайти його → правило з тим способом, що
  пропонується першим; інший — обрати елемент один (REQ-028-15, REQ-027-15).
- Користувач без права змінювати проєкт → вибору немає зовсім, як і зараз (REQ-024-01).
- Undo, коли частину правил не вдалося зберегти → прибирає лише збережені (REQ-028-21, 22).
- Знімок порівнюється знову після кожного з трьох правил → до кінця дії кнопки дій недоступні,
  повторна дія не запускається (REQ-028-20).

## Ключові сутності

- **Вибір** — до трьох елементів одного знімка (еталона або знімка) в порядку, в якому їх
  обрали; номер — місце в цьому порядку. Не зберігається.
- **Правило елемента** — без змін: одне на селектор (REQ-002-12).

## Припущення

- Ліміт три елементи, бо кожне правило порівнює знімок знову; якщо його виявиться мало, змінимо
  число окремим рішенням власника продукту.
- По одному правилу на елемент (рішення власника продукту): так кожне видно й прибирається окремо
  в «What's compared» (REQ-024-23).

## Поза межами

- Вибір рамкою мишею: плутається з малюванням областей, а для трьох елементів не потрібен.
- Одне правило з кількома селекторами: змінює модель правил.
- Вибір одночасно на еталоні й на знімку: номери не збігалися б для елементів, яких немає на
  одному з них.
- Вибір кількох у списку змін вкладки Changes і в підказках про шум.

## Рішення

- 2026-10-29, власник продукту: по одному правилу на кожен елемент; вибір лише на тому знімку, з
  яким працюємо; не більше трьох елементів.
- 2026-10-30, власник продукту: панель вибору може лежати поверх знімка, але не поверх обраних
  елементів (SC-028-03). Зменшувати знімок під панель не можна: його масштаб після появи не
  змінюється ([018](../018-ui-redesign/spec.md)).
